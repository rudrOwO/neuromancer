# Neuromancer Project Analysis

> This document was generated by Claude (Opus 4.5) on 2026-01-28.

## Project Overview

**Neuromancer** is a real-time 3D neural network visualizer for MNIST digit recognition. Users draw digits on a canvas and watch the CNN process their input through convolutional and pooling layers in an interactive 3D environment.

---

## Strong Sides

### 1. Excellent Architecture Decisions
- **Web Worker separation** (`web/onnx/`) keeps heavy ML inference off the main thread, ensuring smooth 60fps UI
- **Transferable objects** in `bridge.ts:89` - zero-copy ArrayBuffer transfer between threads, avoiding expensive serialization

### 2. Modern Tech Stack
- **Svelte 5 Runes** (`$state`, `$derived`, `$effect`) - latest reactive patterns, cleaner than stores
- **Threlte** for declarative Three.js - great DX for 3D visualization
- **ONNX Runtime WASM** with SIMD threading - near-native inference performance

### 3. Smart Performance Optimizations
- **Model warmup** (`runmodel.ts:22-34`) - pre-warms JIT compilation
- **30 FPS throttling** (`DigitCanvas.svelte:192-209`) - balances responsiveness with compute
- **Code splitting** - dynamic imports for 3D assets
- **`willReadFrequently: true`** canvas optimization (`DigitCanvas.svelte:217`)

### 4. Clean Code Organization
- **Path aliases** (`@components/*`, `@utils/*`) - clean imports
- **Separation of concerns** - bridge, state, UI, and ONNX layers are well-isolated
- **TypeScript throughout** with explicit type definitions

### 5. Good UX Touches
- First-visit hint system
- Responsive design (mobile canvas, desktop 3D)
- Smooth bezier curve drawing (`DigitCanvas.svelte:174-181`)

### 6. Python Model Pipeline
- Scripts to add visualization-friendly post-processing (bias, clip, softmax)
- Well-documented ONNX manipulation

## Performance Recommendations

### 1. Consider WebGL Execution Provider

**`runmodel.ts:17-19`** - currently uses WASM only:
```typescript
// Current
executionProviders: ["wasm"]

// Recommended - try WebGL first, fallback to WASM
executionProviders: ["webgl", "wasm"]
```
WebGL can be 2-5x faster for certain operations on GPUs.

### 2. Implement Buffer Pooling

**`DigitCanvas.svelte:96-102`** - allocates new Float32Arrays every frame:
```typescript
// Current - allocates on every preProcess() call
const inputTensorData = new Float32Array(tensorLength)
const renderTensorData = new Float32Array(tensorLength)

// Recommended - reuse buffers
let inputTensorBuffer: Float32Array | null = null
let renderTensorBuffer: Float32Array | null = null

function getOrCreateBuffer(size: number): Float32Array {
  if (!inputTensorBuffer || inputTensorBuffer.length !== size) {
    inputTensorBuffer = new Float32Array(size)
  }
  return inputTensorBuffer
}
```

### 3. Avoid Recomputing Static Vertices

**`Tensor2D.svelte:47-62`** - vertices computed per component instance but dimensions are static per layer:
```typescript
// Vertices could be cached and shared across all Tensor2D instances
// of the same layer, since they only depend on rows/columns/pointSize
const vertexCache = new Map<string, Float32Array>()

function getVertices(rows: number, columns: number, pointSize: number): Float32Array {
  const key = `${rows}-${columns}-${pointSize}`
  if (!vertexCache.has(key)) {
    // compute and cache
  }
  return vertexCache.get(key)!
}
```

### 4. Debounce or Skip Redundant Inference

**`DigitCanvas.svelte:192-209`** - runs inference even if canvas hasn't changed:
```typescript
// Add a dirty flag to skip inference when canvas is unchanged
let canvasDirty = false

function draw(e: any) {
  // ... existing draw logic
  canvasDirty = true
}

function handleMouseMove(e: any) {
  // ...
  requestAnimationFrame(function (timestamp) {
    if (!canvasDirty || timestamp - lastTime < CANVAS_TICK) return
    canvasDirty = false
    // ... run inference
  })
}
```

### 5. Use `needsUpdate` Instead of Recreating BufferAttributes

**`Tensor2D.svelte:192-214`** - the color BufferAttribute is conditionally rendered, causing recreation:
```typescript
// Current - recreates attribute on highlight toggle
{#if hightlighted}
  <T.BufferAttribute args={[tensorcolor.highlighted, 3]} ... />
{:else}
  <T.BufferAttribute args={[tensorcolor.normal, 3]} ... />
{/if}

// Recommended - update existing attribute in-place
// Use geometry.attributes.color.needsUpdate = true after modifying array
```

### 6. Consider InstancedMesh for Point Clouds

For layers with many similar tensors (like Conv Layer #2 with 16 feature maps), `InstancedMesh` could reduce draw calls significantly.

### 7. Lazy Load Infographics Modal

**`Tensor2D.svelte:100-151`** - the `handleClick` function does expensive tensor operations even though the modal may not be used often. Consider lazy computation:
```typescript
// Defer tensor slicing until modal actually renders
function handleClick() {
  infographicsModal.layerName = layerName
  infographicsModal.computeTensors = () => {
    // Move tensor computation here
  }
  showModal()
}
```
